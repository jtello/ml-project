Predicting Car
Testing Time

How a data model can shorten the road from configuration to production.

01 — THE PROBLEM

Every car sits on the bench before it ships

  • Each configuration is physically tested before it reaches the line.
  • Testing time swings widely between configurations — some finish fast, others take far longer.
  • Long, unpredictable tests slow the line and add cost.
  • Per Kaggle: more time on the bench also means more CO2 emitted — faster testing, without lowering safety standards, is the “greener” in Greener Manufacturing.
02 — THE PRODUCT

Turn a configuration into a time estimate

Input

A car's configuration — the options and features selected.

Output

A predicted testing time, in seconds.

The estimate arrives before the car ever reaches the bench.

Example: one configuration in the data — anonymized codes like X0=k, X1=v, X2=at, plus around 360 option flags — took 130.81 seconds on the bench.

03 — THE VALUE

Three ways this pays for itself

Scheduling

Route long-testing configurations to open slots instead of creating bottlenecks.

Early Warning

Flag unusual configurations likely to need extra testing time.

Faster Iteration

Engineering gets a time estimate without waiting on the physical test.

04 — OUR APPROACH

Tested five methods, kept the one that generalized

  • Each car comes with 364 data points: 8 descriptive tags (like trim or option codes) and 356 simple on/off switches (is this feature installed or not).
  • Compared Linear Regression, Decision Tree, Random Forest, KNN, and XGBoost.
  • Tuned and validated each with cross-validation, to avoid trusting one lucky split of the data.
  • XGBoost came out ahead — a model built for exactly this kind of structured, feature-heavy data.

07 — RECOMMENDATIONS

Use it to schedule, not to replace testing

  • Trust the model for standard configurations — prioritize and schedule with confidence.
  • Route high-range predictions to manual review instead of automatic scheduling.
  • Treat this as a scheduling aid, not a substitute for the physical test.
08 — NEXT STEPS

Closing the gap on rare configurations

  • Collect more examples of long-testing configurations.
  • Retrain on a regular cadence as new results come in.
  • Package the model as a tool the scheduling team can run directly.
